# 产品板 FFmpeg 对齐：来源门未通过

本轮只复核本机上一轮保存的库与原始 REA 记录，未连接板子、未重新分析、未发布产品库的真实函数名对应关系或伪代码。当前不能补齐报告的产品板代码列。

| 核验项 | 结果与边界 |
|---|---|
| 本机材料 | 库本体、路径映射、原始 MCP 响应、decoded 投影和只读 ELF 属性记录均存在，仍仅保留在忽略目录 |
| 样本与证据身份 | 本机库与先前保存的板上校验值一致；两函数的原始响应/decoded、Ghidra provider 及样本身份匹配 |
| 函数对齐 | 本机已核对两份现存真实函数体与既有对照目标一致；来源门通过前，不公开产品占位名与真实函数名的映射或代码 |
| 版本 | 已有包版本在本机可读；来源门通过后才整理允许的大版本描述，不公开精确版本或构建标识 |
| 已证实的来源范围 | 原包记录声明 FFmpeg、开源许可证和上游 URL；这支持开源来源声明 |
| 尚未证实的前提 | 这些元数据不能证明未经厂商改动；保留的来源记录没有与该库绑定的完整源码 revision/补丁清单或可核验的未修改构建说明 |
| 当前镜像关联 | PM已说明板子重新烧录；缓存属于上一轮采样，不代表新镜像中的库。本轮没有访问新镜像 |

“无法确认未经改动”不等于发现了厂商补丁，也不等于许可证不适用。本轮要求以确认未修改为公开真实代码的前提，因此不能用许可证、URL、公开 API 同名或少数函数相似代替该证明。

已读的两列公开基线为[既有比较](../../ffmpeg-demo/comparison.md)、[开源板比例换算函数](../../ffmpeg-demo/board/av_packet_rescale_ts/pseudocode.decoded.json)、[开源板尺寸对齐函数](../../ffmpeg-demo/board/avcodec_align_dimensions2/pseudocode.decoded.json)及[上游裸编译证据](../../ffmpeg-demo/upstream/)。它们不证明产品库没有下游修改；既有[产品板脱敏效果报告](../re-effect.md)也只确认开源来源声明与有限函数恢复效果。

按本轮“来源无法确认则停止”的要求，本次不生成产品伪代码文件、产品库实名加固属性或三状态完成表。原始 REA 记录和本机库保持私有，没有用其他工具输出冒充 REA。

需要 PM 补充与缓存库对应的源码/补丁记录（若无补丁，需明确记载），或可核验的未修改上游构建依据。材料只需给出本机位置或核验方式，无须公开私有路径或构建指纹。来源门通过后再继续复用已有伪代码；若要改用新镜像样本，另需重新绑定其身份。
