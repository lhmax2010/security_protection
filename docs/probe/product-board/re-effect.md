# 产品板真实代码的逆向效果（脱敏）

在本轮实测的一份开源来源媒体库lib_S上，Full RELRO、NX、strip及canary/FORTIFY导入没有阻止REA/Ghidra取得两个公开函数的真实实现汇编与伪代码，主要计算路径仍可辨识。结论仅限这一库和两个函数，不推断私有算法或整个产品。

该库先通过板上包的开源许可证与上游项目声明核验来源，再仅拉取这一份到本机；本机文件与板上SHA256一致。它独立于30个属性样本的统计分母。真实路径、包名、版本指纹、库本体、原始MCP响应及decoded投影均保留在本机忽略目录，未公开。

分析使用REA 6.4.0、Ghidra provider 12.1.4，仅静态读取，未执行库函数、未注入或在板上运行负载。两个函数均通过公开名字直接取得实现，REA确认有函数体，且不是外部桩或thunk；未请求完整函数或字符串清单。

| 观察项 | 脱敏结果 | 能支持的结论 |
|---|---|---|
| 名字定位 | strip后的两个公开入口仍能按名字直接解析 | strip删除普通符号表，仍保留必要的动态接口线索 |
| public_1：比例换算逻辑 | 条件分支、公开比例换算辅助调用及栈检查失败路径均出现在伪代码中；同时取得非空汇编 | 可理解主干计算与防护检查，未被加固属性遮蔽 |
| public_2：尺寸对齐逻辑 | 像素格式描述辅助调用、条件/switch分支、加法与位运算均保留；同时取得非空汇编 | 格式相关的分支和对齐计算仍可追踪，不是只有函数名 |
| 函数内栈保护 | 两个实现均可见栈检查失败调用；历史开源板同两个函数的既有伪代码未见该调用 | 这两个函数的防攻击检查更明确，但原计算主干仍可恢复 |
| 整库属性 | 产品lib_S为Full RELRO；历史对应开源板库为None RELRO；两边均有NX、strip和canary/FORTIFY导入证据 | 该库部分加固确有增强；导入不能反推精确flag或全函数覆盖 |
| 恢复限度 | 有通用参数名和低层表示，原类型/变量语义需要人工解释；未做运行时等价验证 | 得到的是可解释的反编译逻辑，不是原始源码完整恢复 |

首轮本机脚本沿用了旧MCP SDK三参数调用，超时选项未生效，原始错误为`SdkError: Request timed out`，代码`REQUEST_TIMEOUT`；没有把它计为分析成功。核实本机SDK的`callTool(params, options)`接口后修正超时参数，另存新一轮响应并成功取得上述证据。失败原响应没有覆盖。

首次名字搜索把正则锚点当成了默认literal模式的普通字符，返回0；这不是防护效果。改为实际名字的literal搜索后，两者各匹配1个，直接函数查询也均成功。全部原始响应分开保留，避免把错误查询包装成“名字被隐藏”。

本轮已证明：至少这两个开源函数在实际产品库加固更强的情况下仍可被静态反汇编并解释主要逻辑。不能据此宣称所有产品代码都容易恢复，也不能证明代码混淆、选择性字符串加密、反调试或厂商私有保护完全不存在。strip已是广泛采用的名字层措施，反逆向不能笼统称为空白；对算法读懂的额外阻碍在本次两个公开实现中未得到足够证据。
