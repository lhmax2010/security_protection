# 产品板当前防护清单（脱敏）

实测对象为 Tizen 10.0.0 TV / armv7l，先完成经授权的开发模式/sdbd设置。下表反映该采样状态，不代表出厂默认状态；30个定向样本（12可执行、18共享库）与历史开源板27个样本不是配对或随机抽样，不能推算全产品覆盖。

| 措施 | 产品板实测 | 历史开源板 | 归类与边界 |
|---|---|---|---|
| Full RELRO | 6/30（20.00%）；Partial 21，None 3 | 8/27（29.63%） | 防攻击加固；本队列比例更低 |
| NX栈请求 | 30/30（100%） | 27/27（100%） | 防攻击加固；ELF请求，未做运行时探测 |
| PIE（仅可执行） | 10/12（83.33%） | 11/11（100%） | 防攻击加固；共享库不计分母 |
| canary辅助导入 | 28/30（93.33%） | 21/27（77.78%） | 防攻击加固；另1个provider-only，不代表全函数覆盖 |
| FORTIFY辅助导入 | 25/30（83.33%） | 17/27（62.96%） | 防攻击加固；另1个provider-only，不能反推精确flag |
| strip（无.symtab） | 29/30（96.67%） | 27/27（100%） | 去除普通名字的反逆向措施；指令仍在 |
| 导出名字收敛 | 6/30无定义动态导出；其余仅发布数量级；12/24有导出的样本以C++ mangled项为多数 | 本轮不重采历史符号 | 反逆向/接口治理；没有API白名单，不能判定必要导出或内部泄漏 |
| RPATH / RUNPATH | 0/30 / 9/30；值不公开 | 0/27 / 8/27 | 链接搜索配置；仅凭存在不能判定路径安全 |
| SMACK | 已挂载 | 已挂载 | 隔离；不读取规则，不验证策略有效性 |
| 内核ASLR | 2 | 2 | 防攻击加固；未观察实际地址分布 |
| 根挂载只读 | 当前rw | 历史ro | 完整性/写保护；当前产品板未观察到根挂载只读 |
| dm-verity/启动完整性 | 有内核接口、device-mapper与启动关键词痕迹；强制状态未知 | 历史有限查询未见相关痕迹 | 完整性；不能据痕迹确认验证链生效 |
| Secure boot / TEE | 标准接口有限查询未见；真实状态未知 | 无同口径历史数据 | 完整性/隔离；不排除厂商实现 |
| 应用加密 | 有限挂载检查未发现常见加密层；应用加密未知 | 无同口径历史数据 | 防读懂/完整性；不检查私有应用内容 |
| 加壳/代码混淆/字符串加密 | 30/30未见所查已知packer段名或W+X装载异常；30/30有限rodata窗口仍有可打印片段 | 未做同口径比较 | 反逆向；不能排除选择性加密、自定义壳或混淆 |

产品队列的canary/FORTIFY导入证据比例更高，但Full RELRO、PIE、strip比例更低；当前根挂载为rw，因此不存在“产品板所有防护都更强”的证据。版本、组件与样本选择不同，也不能把这些比例差异归因为编译器。

另对一份已由包许可证与上游信息确认开源来源的媒体库（占位名lib_S，独立于30样本分母）进行验证：Full RELRO、NX、strip及canary/FORTIFY导入均检出。该库历史开源板对应样本为None RELRO，其余上述导入/NX/strip已存在，所以本库RELRO画像确有增强。只凭这些属性不能证明具体采用了某一hardened构建选项或全函数SSP；本轮不反推构建flag。

lib_S的板上与本机Lua字段逐项一致，GNU readelf另复核RELRO/NX/strip一致；仅这一个已确认开源来源的库被拉到本机，没有拉取私有库。REA效果将据实际伪代码填写，当前尚未作可读性结论。

反逆向不能笼统称为空白：strip已广泛存在，动态导出仍可提供名字线索；本轮尚无足够证据确认代码混淆、敏感字符串加密、私有算法不可恢复或这些保护完全缺席。私有函数没有反编译。

属性与方法见[hardening-summary.txt](hardening-summary.txt)、[hardening-matrix.txt](hardening-matrix.txt)、[anti-re-signs.txt](anti-re-signs.txt)与[platform-mechanisms.txt](platform-mechanisms.txt)。公开文件仅含占位名、统计与脱敏描述；路径映射、库本体、原始输出及REA原始响应只在本机忽略目录。
